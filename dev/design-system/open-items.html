Design system: the last open items

Everything still open, on one page. There are three decisions: two about the text colours (§1) and one about row alignment (§2). §3 lists what is already settled and §4 what comes after, which is work rather than decisions. The cards use the real token file and Open Sans; the columns differ only in colour or position.

1Text colours: where the two old names go

You decided on three text levels: default (near black), muted (mid grey) and disabled (light grey, only for disabled controls). Two old names still carry other greys: text-secondary (grey-700, 74 uses) and text-subtle (grey-400, 101 uses, 2.5:1 on white, too light to read). Neither can simply be renamed, because each is used for several jobs. Each job goes to one of the three levels. I checked every use across the packages; this is the mapping.

Q1 Headings: default or muted?

Labels went to muted because they describe the thing next to them. A heading names a region, and with muted headings a card has no near-black text above the values. A table's column name is a heading too, and its type label sits right under it in muted, so a muted column name would look the same as its type.

A. Default

Weight and size set the heading apart from the labels; colour separates labels from values.

Q2 Placeholders: muted or light?

A placeholder is often the only hint of what goes in a field ("e.g. 10", "Search columns"). Light grey is the common look, but at 2.5:1 the hint is hard to read. GitHub's Primer and Material both draw placeholders in their muted text colour. What separates a placeholder from a value is then the colour step (4.8:1 against 17.7:1).

2Rows: where the content starts when the handle is hidden

With option E the drag handle only appears on hover. If it still takes its space at rest, every row starts 18px to the right of the label above it, which is what you noticed. The dashed red line marks the label's left edge. Hover or tab into the rows.

Proposal: B, handle in the margin. Content lines up with the labels at rest, and the handle is still where people look for one. It needs about 14px of padding left of the content, which block cards have. C is the runner-up; it drops out wherever clicking a row already does something else (open, edit), so it cannot be the one rule.

3Settled

  • Names: accent for the blue; three text levels; surfaces page / surface / raised plus subtle, field, hover, selected; text-, bg-, border- for danger, warning, success; --blockr-<owner>-* for local settings; old names kept as aliases.
  • Labels: muted, 12px, 4px above the input.
  • Input borders: stay soft (border-default).
  • Empty required input: soft amber border stays.
  • Small icons: option E, thin shapes in muted, shown on hover or focus, remove turns red on hover.
  • Block category colours: Okabe-Ito, unchanged.
  • Font: Open Sans (bslib's Shiny default), switchable later through one variable.
