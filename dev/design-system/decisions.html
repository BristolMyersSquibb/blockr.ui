Design tokens: what you have to decide

The problem in one line: blockr's colour variables have grown to 91 names, often several for the same thing, and one of them ambiguous. Before the design system can be written down, each thing needs exactly one name. Four of the six items are real design choices; the last two just need a yes. Each shows the proposal. The full reasoning and counts are in naming.md next to this file.

1. The blue: "primary" or "accent"?

"Primary" currently means two unrelated things, both in constant use:

This body text is --blockr-color-text-primary
near-black text, 125 uses
Apply
the blue is --blockr-color-primary, 226 uses

Options

A. Call the blue accent (color-text-accent, color-bg-accent, ...), and the text color-text-default.
B. Keep the blue as primary, rename only the text to color-text-default.

Proposal: A. It also sets up theming: a theme swaps the accent ramp, and "accent" still means the right thing when the theme is teal. Renames go through aliases (item 6), so nothing breaks.

2. Text: three levels instead of five

Five names are in use for four greys. Grey-700 and grey-900 are only 1.7:1 apart, so "secondary" text reads as main text. Grey-400 fails the WCAG contrast minimum as text, on white and everywhere else, and it is the text colour in 258 places.

Proposal: default (900), muted (500), disabled (400). Visible consequence: secondary text and placeholders get darker, and grey-400 is only used for disabled controls, which WCAG exempts. Also: muted text should not sit on grey-100.

3. Backgrounds: one model instead of seven-plus names

Backgrounds go by bg, bg-muted, bg-subtle, surface, surface-2, surface-muted, bg-input and more, because nobody ever defined what sits on what. Proposal: layers, each sitting on the one before.

One open value

A quiet fill inside a panel (bg-subtle) is grey-50 in most places and grey-100 in viz and dm. Pick one:

grey-50: barely there
grey-100: visible
Proposal: the layer names as shown, and grey-50 for bg-subtle, so grey-100 keeps meaning "interaction" (hover, selected).

Two sub-choices

error vs danger: merge into one name, danger (the old spec already says "red is one colour").
warning: the old spec and eight uses say #f59e0b; my theme branch said #d97706.

Proposal: text, fill and border for danger, warning, success over a small red, amber and green ramp; error merges into danger; warning is #f59e0b.

5. Local settings get their owner's name (just a yes)

Some variables look global but belong to one component: --blockr-spinner-delay and --blockr-sidebar-width-left (dock), --blockr-rank-fill (viz). They become --blockr-dock-spinner-delay, --blockr-viz-rank-fill. Then any name whose second word is not color, font, radius etc. is visibly local, and the tests can check it.

6. Renames go through aliases (just a yes)

For a release, the old name keeps working and points at the new one, and the token tests warn when a package still uses it. Packages move over when convenient. Nothing breaks on any day.
